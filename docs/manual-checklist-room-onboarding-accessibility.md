# 방·온보딩·참여·접근성 수동 점검

아래 항목은 실행 결과가 아닌 검증 절차입니다. 테스트용 계정 A/B/C와 방의 과제를 사용하세요.
폭 320px, 390px, 768px, 1440px에서 각각 작게/기본/크게 설정으로 반복합니다.
Android TalkBack, iOS VoiceOver, 웹 키보드 탐색도 별도로 확인하세요.

## 방과 과제

- [ ] 방 목록의 `팀 작업 공간 · 방` 헤더와 3px 강조 테두리, 내부 과제의 1px 테두리가 구분된다.
- [ ] 방 이름·과제명을 80자 이상으로 만들고 말줄임, 줄바꿈, 버튼 가림과 가로 넘침을 점검한다.
- [ ] 과제 상단 `방 이름 / 과제 이름`을 확인하고 방 링크로 목록에 돌아간다.
- [ ] 방 입장·초대·생성·관리와 과제 생성·이동·수정 동작을 회귀 점검한다.
- [ ] 넓은 웹 사이드바에 `아이디어에서 결과물까지`가 없다.

## 온보딩과 설정

- [ ] 새 계정 첫 로그인 후 네 단계 안내가 보인다. 예시 둘러보기는 기존 샘플만 보여준다.
- [ ] 예시를 열고 닫기 전후 DB의 방/과제/아이디어 개수가 동일하다.
- [ ] 시작하기 또는 다시 보지 않기를 누르고 새로고침해도 다시 열리지 않는다.
- [ ] 나중에 보기는 즉시 홈 사용이 가능하고 완료 상태를 저장하지 않는다.
- [ ] 내 정보 → 앱 설정 → 온보딩 다시 보기로 재진입한다.
- [ ] A에서 완료 후 B로 로그인하면 B의 상태와 글자 크기가 독립적으로 적용된다.
- [ ] AsyncStorage의 `experience:v1:<사용자 ID>`를 잘못된 JSON으로 바꾸거나 읽기/쓰기를 실패시키고 홈 진입 및 설정 오류 안내를 확인한다.
- [ ] 글자 크기 작게/기본/크게가 본문, 과제 제목, CTA, 마감, 입력창에 반영된다. 최소 글자 크기는 14다.
- [ ] 앱 재시작 후 선택값이 유지되며, 큰 글자와 OS 글자 확대를 함께 켜도 주요 기능에 접근 가능하다.

## 평가와 카카오톡 복사

- [ ] 평가할 아이디어가 있는 방 과제에서 일부 인원만 평가하면 두 버튼이 나타난다.
- [ ] 각 인원이 현재 평가 라운드의 모든 아이디어를 평가한 후 두 버튼이 사라진다.
- [ ] 평가가 없는 과제, 멤버를 읽지 못한 상태, 평가 현황 로딩/오류에서는 버튼이 나타나지 않는다.
- [ ] 연결을 끊어 평가 현황 오류를 확인하고 복구 후 화면 재진입한다.
- [ ] 24자 제목 유지, 25자 제목의 앞 23자+…를 확인한다. 한글·영문·이모지로 반복한다.
- [ ] 텍스트 편집기에 붙여넣어 요청된 프레임·줄바꿈·인원·마감일과 정확히 일치하는지 확인한다.
- [ ] 마감일이 없을 때 `🗓 마감: 미정`이 나온다.
- [ ] 성공 토스트는 `카카오톡을 열어 단톡방에 붙여넣어 주세요.`다.
- [ ] 클립보드 권한 거부 시 성공 토스트 없이 실패 안내와 재시도가 가능하다.
- [ ] 메시지에 발송자·미완료자 이름, 내부 식별자, 바로가기 링크가 추가되지 않는다.
- [ ] 시스템 공유창, 카카오 SDK, 이미지 생성이 호출되지 않는다.

## 익명 리마인드와 DB 권한 (migration 적용 후)

- [ ] A가 전송하면 미완료자인 B의 알림 화면에 익명 리마인드가 보인다. 화면은 30초마다 활성 상태에서 갱신된다.
- [ ] 이미 완료한 C에게는 알림이 생성되지 않는다. 현재 라운드의 일부 아이디어 평가만 완료한 B는 대상이다.
- [ ] B의 알림 수신 스위치를 끄고 쿨다운 후 전송하면 B에게 새 알림이 없다. 모든 대상이 거부했을 때 수신 거부 안내가 나온다.
- [ ] 같은 과제에 다른 발송자로 재시도해도 1시간 쿨다운 안내가 나온다.
- [ ] A가 서로 다른 과제에 5회 전송한 후 6회째에 일일 제한 안내가 나온다. 날짜 경계는 Asia/Seoul이다.
- [ ] 동시 요청으로 1시간/일일 제한을 우회할 수 없다. 테스트 DB에서 이력 시간을 조절하여 검증한다.
- [ ] 네트워크 실패·migration 미적용 상태에서 버튼이 오류를 안내하고 다시 활성화된다.
- [ ] A와 B의 네트워크 응답 및 알림 UI에 발송자 이름/ID가 없다. RPC는 상태 문자열만 반환한다.
- [ ] authenticated/anon 역할로 `reminder_dispatches`를 SELECT/INSERT/UPDATE/DELETE하면 거부된다.
- [ ] B는 자신의 `reminder_notifications`만 조회하고 `isread`만 수정할 수 있다. recipientid/projectid 수정, 직접 INSERT는 거부된다.
- [ ] 다른 사용자의 수신 설정을 조회·변경할 수 없다.
- [ ] 방 비회원이 RPC를 호출하면 forbidden이다. 기존 방/과제 권한은 그대로다.
- [ ] 알림 읽음 상태가 재접속 후 유지되고, 빈 목록·로딩·실패·재시도가 표시된다.

## 접근성과 회귀

- [ ] 리마인드·복사·온보딩 버튼, 글자 크기 선택, 수신 스위치의 역할/라벨/상태를 스크린리더로 확인한다.
- [ ] 기존 아이디어 즐겨찾기 메뉴와 즐겨찾기 필터의 라벨·선택 상태를 확인한다. 현재 모델에 과제 즐겨찾기는 없다.
- [ ] 기존 단계 탭, 마인드맵 접기/펼치기, 내보내기 라벨을 확인한다.
- [ ] 로그인, 아이디어 입력, 평가, 결과 화면의 기존 흐름을 점검한다.

## 자동 검증 명령

```sh
npm test
node --experimental-strip-types --test --test-isolation=none tests/room-onboarding-accessibility.test.mjs
node node_modules/typescript/bin/tsc --noEmit
```

이번 환경에서 실제 DB RLS·동시성 및 모바일/브라우저 상호작용 검증은 수행하지 못했다. 로컬 Docker 엔진이 실행 중이 아니며, 전체 타입 검사에는 기존 발표 화면과 example/EXPO1 복제 폴더 오류가 남아 있다.
